# 科研汇报参考版式

本指南配合包内 [AeroDuo 六页参考稿](../examples/aeroduo-reference/AeroDuo_组会汇报_合并精简6页版.pdf)，说明如何用图表、机制关系和同屏对照组织科研汇报。网页端与客户端使用同一份参考，逐页索引见 [参考阅读说明](../examples/aeroduo-reference/README.md)。用户指定其他模板时优先采用用户模板。

这是一份汇报设计对照，未凭参考幻灯片核验原论文，不能把其中技术表述作为新论文的事实来源。

## 页面组织原则

| 内容 | 参考组织方式 | 迁移到新论文 |
|---|---|---|
| 任务与数据 | 第 1 页用场景、角色分工、成功判定和数据构成解释任务 | 首个内容页用任务实例加输入/职责/输出对照；相关数据构建可放下方 |
| 研究定位 | 第 1–2 页把研究切入点融入任务和方法接口 | 选择能解释切入点的相关路线，需要逐项比较时再分组 |
| 方法总览 | 第 2 页把总体流程压成顶条，主体展开两项关键机制 | 总览条负责定位，主体解释困难的变换，用局部图连接输入输出 |
| 执行与训练 | 第 3 页并列职责链，第 4 页展开监督产生与评测协议 | 按数据、监督和控制关系组织，标清信号来源、作用位置及部署条件 |
| 实验 | 第 5 页将主表、消融和案例并列 | 让主结果与解释它的消融/案例相邻，保留必要行列与不利结果；复杂时展开为多页 |
| 总结 | 第 6 页区分贡献、证据边界、复现疑点与讨论 | 每项贡献绑定证据，每项局限说明影响；后续设想另行标识 |

**不要把“少字”误写成机械限字。** 数据页可以包含较多字符；有效密度来自同屏对照、结构关系和证据覆盖。表格是否可读仍需按实际画布和放映尺寸检查，不机械复制参考稿最密集的数据页。

这些结构可以在同页形成 A/B/C 分区，也可以按内容展开为多页。先按 [分区与完整性指南](panel-planning.md) 列全内容，再选择布局；不以参考稿页数或分区数为上限。

## 可直接选择的六种结构

以下占比以**去掉标题和页脚后的正文区**为基准，是布置起点；按当前证据调整。原生线条和箭头用于解释论文关系，不用于装饰。

### A. 场景 + 任务契约 + 数据形成

适合任务定义、系统角色或新数据集。顶部约 60–65%：左侧 35–40% 放同一任务的互补视角或失败实例，右侧为输入/观测/职责/输出对照。底部放数据来源、构建步骤、划分与判定标准。

视觉锚点是具体任务实例；对照表解释“谁看见什么、谁决定什么”。不要为不存在的数据集强加统计数字。数据构建不是论文重点时，用必要的任务边界替换。

### B. 总览条 + 双机制展开

适合总体架构与两个紧密关联的关键模块。正文顶部约 15–20% 是 4–5 步总流程，边上标出传递对象；余下分给表示构建和推理/控制机制。

每个主体必须包含中间产物或具体变换，不只是模块名。跨模块数据用同一变量或颜色相连，反馈线说明触发条件。不要将总流程的每个节点在下方再抄一遍。

### C. 并行职责 + 共享闭环条件

适合调度、导航/检测并行、感知/规划/控制分工。两到三列按职责安排；每列用短链表示输入、算法、输出，并标注必要频率或条件；下方一条横向闭环说明何时重规划或终止。

列内有原图或中间状态就贴近对应操作；没有图时可用可编辑流程与变量。三个模块不意味着三张大段落卡片。

### D. 训练与推理泳道

适合特权学习、蒸馏、自监督或阶段训练。左右/上下泳道明确区分可用输入、计算模块、监督来源、更新参数和部署输出；共享部分对齐，只在不同处强调。

关键损失靠近监督边，箭头标清梯度或数据方向。最多展示能解释差异的必要公式，其余进备注。条件、频率、采样和网络规模贴近相应阶段；不能把训练专有信息画成部署输入。

### E. 主结果 + 机制证据 + 案例

适合结果与消融形成解释链。正文左侧约 65–75% 放主表及相关消融，右侧放轨迹、热图或失败实例；单纯趋势比较也可使用原生曲线/柱状图。

高亮当前方法与真正需要比较的行；表头保留数据划分、单位、指标方向。各分区保留能回指到行/列的发现，可以讲多个结果和边界。消融不单调或子集表现反转时明确说明，不能挑有利数字。没有定性证据时把右侧空间给原生数据图，不用装饰图补齐。

### F. 贡献—证据—边界

适合总结。按对应关系排版：机制贡献旁边就是支持的实验和未被证明的部分；必要时另加复现疑点。底部提出一项具体组会问题或可验证的后续假设。

可以用三列，但不要求每列恰好三项。没有依据的“未来工作”不补造。不要重复前页段落或把论文的失败案例误归因给其他方法。

## 一个反例改写：训练机制页

低效安排：上方三个同质框分别解释三个损失，中间摆总损失，底部摆链式法则；下一页再描述真实环境、筛选和评分。虽然文字不算很多，听众仍需自己拼出训练逻辑。

更好的组织：左侧训练泳道显示“观测 → 网络候选 → 可微轨迹 → 代价 → 参数更新”，监督环境连向代价节点；右侧推理泳道显示“当前观测 → 同一网络 → 评分选择 → 执行”。用来源可核对的标注说明训练与部署的信息差异，把损失放在它实际作用的边上。若原论文没有该流程，就按真实机制改写，不能照抄这个示意。

## 防止参考稿变成模板束缚

- 学习分工、接口、对照和空间使用，不复制论文事实，不强制所有论文使用双机或双模块叙事。
- 保留必要精确数据，但不把“完整表格”当成所有列都必须挤到一页的理由。
- 参考稿用了某种字体或配色，不自动覆盖用户明确的字体要求。
- 技术结构与版式一致性可以共存；连续多页同构时，要确认其语义真的并行。
