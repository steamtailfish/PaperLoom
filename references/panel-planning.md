# 多分区汇报与内容完整性

以完整讲清论文为目标。每页可以讲多个点，用 A/B/C/D 等小标题划分阅读区域。论文内容多时增加正文页，分区密度与全套内容覆盖同时满足；六页参考稿提供布局参考，不限定成品页数。

## 从内容清单出发

通读论文，逐小节、逐图表和相关附录建立 `content_inventory`。每项记录稳定 ID、主题、来源定位与 `required_on_slide`。核心贡献对应的机制、输入输出、训练和执行过程、评测设置、主结果、消融、敏感性、不利结果和局限应在正文可见。论文没有某项内容时如实记录，不为了齐全编造。

清单粒度必须能发现遗漏。“方法全部”“实验全部”这样的一个条目不能代表整章。按需要解释的模块、实验问题和数据表拆分，重复材料可合并；原始图表各自要有去向。非核心补充可放备注或略去，写明 `exclusion_reason`。重要内容不能因为放不下就标成非核心。

## 从主题到 A/B/C 分区

每页先安排 3–5 个实质分区作为构图起点，每区可容纳多个要点。两个复杂区、一张完整主表或复杂案例可以独占页面，在 `panel_count_reason` 说明可读性依据。标题栏、页码、图例、同一流程的几个节点不单独计为内容区。

每个 `panels` 元素包含：

- `label`：A、B、C 等页内定位字母，正文实际显示。
- `title`：具体子主题，如“观测与地图更新”，避免“创新点一”。
- `content_ids`：本区真正呈现的清单条目 ID。
- `key_points`：本区要讲清的操作、对照或发现，可多条，不以总字数截断。
- `visual`：本区图表或原生对象如何解释内容，不能只写“放一张图”。

分区可采用上宽下双栏、左侧主机制加右侧两个证据区、两行不等宽区或流程条加下方展开。共享主图时用局部标注把分区与对应部位连接。不要把整页拆成相同大小的文字卡片。

| 页主题 | A 区 | B 区 | C 区 | 需要时增加的区域或正文页 |
|---|---|---|---|---|
| 任务与数据 | 任务实例、输入输出与判定 | 数据形成、规模与划分 | 现有路线与研究切入点 | 协议差异与数据修订细节 |
| 地图或表示机制 | 输入、坐标与状态维护 | 编码、融合和中间表示 | 输出接口与模块对照 | 内部变换、必要公式和具体算例 |
| 分层执行 | 高层决策使用什么信息 | 低层控制和动作产生 | 更新、停止与失败条件 | 时序交互、轨迹案例与设计依据 |
| 训练 | 示范与监督形成 | 优化目标及参数更新 | 训练到推理的差异 | 奖励设计、实施设置、敏感性实验 |
| 实验 | 主要对照与条件 | 消融或参数敏感性 | 定性案例、不利结果与边界 | 完整大表、跨数据集结果或失败分析 |

这些是内容组织选项，不要求每篇论文都有相同模块。不要从参考汇报借来当前论文不存在的技术细节。

## 放不下时增加页数

先删除重复措辞和无效间距，保持必要图例、表头和可读字号。仍然拥挤就按子问题新增正文页，例如“表示构建”和“表示内部操作”，“训练信号”和“优化配置”。扩展页依然承载多个相关点，不能变成每个标签一页。

增加页数也用于展开尚未讲清的内容，而不只用于处理文字溢出。大型表格已需要整页时保留独立页，在另一页展开消融、案例和解释。没有用户硬性页数要求时，不为目标数字删核心内容、不把重要机制仅塞进备注或附录。用户明确限页时遵守要求，并说明无法展开的范围，不暗中改变页数。

## 检查与追踪

使用 [计划模板](../examples/slide-plan.template.json)，参考 [虚构的分区计划示例](../examples/panel-plan.example.json)。每项必须可见的内容至少进入一个正文分区。运行：

```bash
python scripts/audit_slide_plan.py work/slide-plan.json --report work/plan-audit.json
```

脚本核对清单 ID、分区映射、已声明的页数与遗漏；少分区提示需要人工判断，不是硬性三分区规则。检查不分析论文或 PPTX 语义，也不能发现根本没有录入清单的内容。生成后逐项比对论文、计划和实际页面：确认内容完整、确实可见，A/B/C 各自增加了信息。`review.coverage_verified` 仅在完成这项核对后设为 `true`。
