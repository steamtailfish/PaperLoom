PaperLoom превращает научные статьи в компактные, редактируемые презентации **PowerPoint `.pptx`** с акцентом на иллюстрации, таблицы и диаграммы. Установите навык в клиенте или загрузите ZIP-архив проекта вместе со статьёй в веб-версию GPT с возможностью выполнения кода.

## 🚀 Быстрый старт

### 💻 Локальный клиент

Клонируйте или скачайте этот репозиторий вместе с включёнными шрифтами, ознакомьтесь с [руководством по шрифтам](../../fonts/README.md), затем выполните из корня репозитория:

```bash
python scripts/install_skill.py
```

По умолчанию файлы копируются в `~/.agents/skills/paper-loom/` текущего пользователя. Если такой каталог уже существует, установка останавливается, не перезаписывая вашу версию. В клиенте, поддерживающем импорт навыков, также можно напрямую выбрать всю папку проекта. [Подробное руководство для клиента](../../references/client-mode.md)

После установки выберите PaperLoom в клиенте или введите:

```text
Используй $paper-loom, чтобы подготовить по этой статье презентацию PowerPoint для
семинара исследовательской группы.
Соблюдай требования навыка к структуре, шрифтам, извлечению изображений и редактируемым
формулам; предоставь готовый файл .pptx.
```

### 🌐 Загрузка в веб-версию

Используйте готовый архив релиза **`paper-loom-v1.1.0-full.zip`** и загрузите его вместе с PDF статьи. Если работаете с исходным кодом, создайте архив командой `package_skill.py --variant full`, приведённой ниже: она исключает результаты сборки и личные кеши. Затем отправьте:

```text
Распакуй PaperLoom и создай презентацию статьи по процессу из WEB_START.md.
Сначала прочитай SKILL.md, references/design.md, references/reference-patterns.md и references/quality-gates.md.
Систематизируй доказательства, сохрани slide-plan.json и сразу продолжай создание презентации.
По умолчанию используй 6–8 слайдов, для сложной статьи — 8–10. Не добавляй отдельные страницы
обзора литературы или формул только ради количества.
Размещай связанные механизмы и доказательства на одном слайде. Сохрани условия сравнения,
единицы измерения и неблагоприятные результаты. Соблюдай требования к шрифтам, извлечению
исходных иллюстраций и необходимым редактируемым формулам. Подробные источники и объяснения помести в заметки.
Проверь структуру и качество, отрендери и осмотри каждый слайд, исправь проблемы и предоставь .pptx для скачивания.
```

> [!NOTE]
> Веб-версия GPT должна уметь распаковывать архивы, выполнять код и создавать файлы для скачивания. Загрузка ZIP не предоставляет эти инструменты и не устанавливает навык навсегда. Полные инструкции: [WEB_START.md](../../WEB_START.md).

## 🧭 Структура на основе доказательств

По умолчанию используйте **6–8 слайдов**, для сложной статьи — **8–10**. Явные требования пользователя к числу слайдов и шаблону имеют приоритет. Охватите задачу и её место среди существующих подходов, механизмы, обучение и выполнение, эксперименты и ограничения, выводы. Каждому пункту не требуется отдельный слайд. Обязательного самостоятельного обзора литературы и фиксированного числа слайдов о методе нет.

До создания слайдов прочитайте [правила оформления](../../references/design.md), [композиции и контрпримеры](../../references/reference-patterns.md), [проверки качества](../../references/quality-gates.md). Сохраните `slide-plan.json` в рабочем каталоге по [шаблону плана](../../examples/slide-plan.template.json), затем продолжайте работу, не ожидая по умолчанию утверждения плана.

Объединяйте общий вид механизма, промежуточные состояния и условия обратной связи. Сопоставляйте основные результаты при одинаковом протоколе, абляции и неблагоприятные результаты. Условия сравнения оставляйте рядом с графиками и таблицами, подробные объяснения и источники — в заметках. Используйте [пример компактного представления доказательств](../../examples/evidence-demo/README.md) и проверяйте читаемость каждой страницы.

<details>
<summary><b>Как устроен рабочий процесс</b></summary>

Ниже описан ранний пример GeoNav. Фиксированное число страниц и обзор в шести блоках из этого примера не являются текущими требованиями по умолчанию.

Этот навык вырос из нескольких циклов подготовки и доработки доклада о GeoNav для семинара исследовательской группы: от сокращения материала и выстраивания повествования до работы со шрифтами, редактируемыми формулами и исправлением форматов Office, а затем — удаления поясняющих подвалов и замены большой обзорной таблицы шестью блоками исследовательских направлений. Проверенные приёмы работы собраны здесь в виде повторно используемых инструкций и скриптов.

1. **Определить цели семинара и визуальные требования**: настоящий PPTX, компактное размещение насыщенного содержания, приоритет иллюстраций, таблиц и диаграмм, заданные шрифты и редактируемые формулы.
2. **Прочитать статью и составить индекс подтверждающих материалов**: сопоставить выводы, рисунки и таблицы, условия экспериментов, неудачные случаи и границы применимости выводов.
3. **Сначала организовать доказательства, затем страницы**: связать задачу, механизмы, эксперименты и ограничения; объединять страницы с одной иллюстрацией или одним механизмом, если это сохраняет читаемость.
4. **Подготовить исходные материалы и редактируемые объекты**: напрямую извлечь изображения, создать таблицы и диаграммы как собственные объекты PowerPoint, преобразовать LaTeX в Office Math, задать шрифты для каждого текстового фрагмента (`run`).
5. **Проверить содержание, оформление и совместимость**: отрендерить каждый слайд, сверить данные, исправить недопустимое значение GB2312 `charset=134` на `-122`.
6. **Вносить локальные изменения по обратной связи**: сохранять подробные источники в заметках и важные условия возле иллюстраций, защищая уже согласованные слайды и исправления формата.

Полный процесс описан в [разборе работы над GeoNav](../../examples/geonav/workflow.md).

</details>

## 🛠️ Разработка и проверка

Используйте Python 3.10+ и Node.js 20+. Выполните в корневом каталоге проекта:

```bash
python -m pip install -r requirements.txt
npm install
python scripts/doctor.py
```

Для преобразования формул в собственный формат PowerPoint дополнительно нужна команда `pandoc`; установите её по [официальной документации Pandoc](https://pandoc.org/installing.html). Необходимые шрифты включены в каталог `fonts/`; сведения об их использовании см. в [руководстве по шрифтам](../../fonts/README.md). Если в текущей среде уже есть специализированные инструменты для PowerPoint, менять их необязательно.

<details>
<summary><b>🖼️ Извлечение изображений</b></summary>

```bash
python scripts/extract_pdf_assets.py paper.pdf --output work/paper-assets
```

Результат включает исходные ресурсы и манифест. Поддерживается параметр `--pages 1,3-5`. Один встроенный объект может быть лишь частью рисунка, поэтому необходимо проверить смысловую полноту рисунка (Figure); для полностью векторных рисунков или рисунков с наложенным текстом нельзя автоматически заменять извлечение скриншотами. [Руководство по извлечению изображений](../../references/figure-extraction.md)

</details>

<details>
<summary><b>🧮 Формулы, шрифты и проверка</b></summary>

В исходном PPTX оставьте отдельный абзац для каждой необходимой формулы, например `[[EQ_FUSION]]`, а соответствующий LaTeX укажите в файле сопоставлений:

```bash
python scripts/inject_equations.py draft.pptx math.pptx --mapping equations.json --require-all
python scripts/embed_fonts.py math.pptx final.pptx
python scripts/validate_pptx.py final.pptx --expected-slides 8 --expected-math 3 --report validation.json
```

`8` слайдов и `3` формулы — требования примера GeoNav; для новой статьи скорректируйте значения по необходимости. Если статье не нужны формулы, не добавляйте их только ради количества. Встраивание шрифтов должно соответствовать их собственным лицензиям; по умолчанию встраиваются пять файлов из `fonts/`.

Валидатор проверяет структуру пакета, связи, наборы символов шрифтов, формулы в собственном формате PowerPoint, заполнители и другие элементы, но **не выполняет полную проверку по схемам OOXML и тем более не заменяет проверку в настольной версии Microsoft PowerPoint**. После рендеринга необходимо проверить содержание и оформление каждого слайда. [Руководство по совместимости](../../references/powerpoint-compatibility.md)

</details>

Запуск тестов:

```bash
python -m unittest discover -s tests -v
```

<details>
<summary><b>📦 Сборка архивов для распространения</b></summary>

```bash
python scripts/package_skill.py --variant github --output ../paper-loom-v1.1.0-github.zip
python scripts/package_skill.py --variant full --output ../paper-loom-v1.1.0-full.zip
```

Полный архив включает шрифты из репозитория; упаковщик проверяет наличие всех файлов. Параметр `--variant github` создаёт архив исходного кода без отдельных файлов шрифтов.

</details>
